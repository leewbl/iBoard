# Maintain a project verification skill

Choose one project-local skill previously generated by [create-verification-skill](../create-verification-skill/SKILL.md) and a prepared image for the Git revision under review. Inspect recent changes to commands, routes, and screens for user journeys absent from the map. Require a source location and a user entry point before proposing a new feature record.

```sh
python3 -m workbench.project_verify maintain --repo "$TARGET_REPO" --revision "$REVISION" \
  --skill "$SKILL_DIR" --image "$LOCAL_IMAGE" --out "$EVIDENCE_DIR"
```

The report checks the skill's index, files, source anchors and every mapped journey. The coordinator runs doctor before driving and checks it again after a failed drive. Each drive has its own offline container. Raw stdout, stderr, screenshots when configured, and cleanup evidence survive the pass. Source and file drift are reported separately from failed behavior. Diagnose a behavior failure using the real command or a known-good revision before calling it a product regression.

When a correction belongs in the skill, rerun maintenance with `--manifest "$CORRECTED_CONTRACT" --helpers "$CORRECTED_HELPERS"` and a new evidence directory. Review the full map, exact source citations and runtime proof. A successful changed run exports a verified bundle and a skill-scoped diff. Submit one PR for proven corrections if the task authorizes it. Leave a suspected product regression open with its original evidence and affected path.

- `clean` means the map matches the bundle and all journeys passed on the selected revision.
- `changed` means an offered replacement changed the bundle and passed the full audit.
- `blocked` means source, map, doctor, runtime or cleanup evidence could not support a conclusion. Inspect the individual reports.
