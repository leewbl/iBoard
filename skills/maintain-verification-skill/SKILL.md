# Maintain a project verification skill

Choose one project-local skill previously generated by [create-verification-skill](../create-verification-skill/SKILL.md) and a prepared image for the Git revision under review. If the contract declares an entrypoint inventory, you can review it before launching any containers.

```sh
python3 -m workbench.project_verify discover --repo "$TARGET_REPO" --revision "$REVISION" \
  --manifest "$SKILL_DIR/contract.json" --out "$DISCOVERY_EVIDENCE"
```

`discover` reads Commander registrations on declared receivers and inline option values in declared JSX controls. It resolves quoted command names and direct registrations inside fixed arrays of names, such as OpenClaw's Workshop archive and restore loop. Registrations that use an unresolved name or `addCommand`, and JSX controls with ambiguous options, require review. The report keeps the Git blob and line for each known entrypoint and each unresolved registration. Use `--since "$PREVIOUS_REVISION"` to compare named entrypoints across commits. Inspect receiver aliases, indirect registration helpers, other controls, and routes outside the declared scopes separately. Require a source location and a user entry point before proposing a missing feature.

```sh
python3 -m workbench.project_verify maintain --repo "$TARGET_REPO" --revision "$REVISION" \
  --skill "$SKILL_DIR" --image "$LOCAL_IMAGE" --out "$EVIDENCE_DIR"
```

The report checks the skill's index, files, source anchors and every mapped journey. It also checks any declared entrypoint inventory and withholds a clean verdict if an entrypoint is unmapped, stale or could not be resolved. The coordinator runs doctor before driving and again after a failed drive. Each drive has its own offline container. For browser journeys, the runner checks that the live page identifies the same commit as the attested image and binds the screenshot to the raw report. Raw stdout, stderr, screenshots when configured, and cleanup evidence survive the pass. Source and file drift are reported separately from failed behavior. Diagnose a behavior failure using the real command or a known-good revision before calling it a product regression.

For a journey that declares a `failure_marker`, run a comparison with an independently written probe that verifies the same user-visible behavior. The failing marker must come from an observed mismatch after cleanup. Setup errors, child crashes and timeouts should produce ordinary errors.

```sh
python3 -m workbench.project_triage --repo "$TARGET_REPO" --base "$KNOWN_GOOD" \
  --revision "$CANDIDATE" --image "$KNOWN_GOOD_IMAGE" --manifest "$SKILL_DIR/contract.json" \
  --helpers "$SKILL_DIR/helpers" --journey "$JOURNEY" --oracle "$INDEPENDENT_PROBE" \
  --oracle-marker "$PROBE_PASS" --oracle-failure-marker "$PROBE_FAIL" --out "$TRIAGE_EVIDENCE"
```

The comparison freezes all scripts, checks the baseline image, and overlays the candidate's tracked source on the same runtime. Each script runs twice per revision in fresh containers. A product regression needs passing baseline runs, repeated observed failures from both candidate probes, and healthy doctor checks. A harness gap needs a failing primary probe and repeated independent success. Other conflicts remain inconclusive. Keep the reports with the original failed audit. Candidates that require dependency installation or compilation need a separate runtime comparison before drawing broader conclusions.

When a correction belongs in the skill, rerun maintenance with `--manifest "$CORRECTED_CONTRACT" --helpers "$CORRECTED_HELPERS"` and a new evidence directory. Review the full map, exact source citations and runtime proof. A successful changed run exports a verified bundle and a skill-scoped diff. Submit one PR for proven corrections if the task authorizes it. Leave a suspected product regression open with its original evidence and affected path.

- `clean` means the map matches the bundle and all journeys passed on the selected revision.
- `changed` means an offered replacement changed the bundle and passed the full audit.
- `blocked` means source, map, doctor, runtime or cleanup evidence could not support a conclusion. Inspect the individual reports.
